# Глава 6. Проверка бинарников платформы перед развёртыванием

> **Что дальше.** Последняя тема домена Cluster Setup. Прежде чем запускать `kubelet`,
> `kubeadm` или `kubectl` на ноде, нужно убедиться, что это действительно официальный
> бинарник, а не подменённый по дороге. Это частный случай защиты supply chain (главы
> 18-19), но применительно к самой платформе. Экзаменационная задача обычно проста:
> сравнить хеш - но надо сделать это быстро и без ошибок.

## 6.1. Зачем проверять

Бинарники kubelet и kube-apiserver работают с правами root и имеют полный доступ к
кластеру. Подменённый бинарник (скомпрометированное зеркало, MITM при загрузке, «тот самый
kubectl из чата») - это полный захват кластера. Проверка целостности отвечает на вопрос:
«совпадает ли файл с тем, что опубликовал проект Kubernetes?».

Два уровня проверки:

| Уровень | Чем | Что гарантирует |
|---------|-----|-----------------|
| Целостность | хеш SHA256/SHA512 | файл не повреждён и совпадает с опубликованным хешем |
| Подлинность | подпись (cosign/sigstore) | файл выпущен именно проектом Kubernetes |

## 6.2. Проверка хеша

Официальные бинарники публикуются на `dl.k8s.io` вместе с файлами хешей:

```bash
VER=v1.35.0
curl -LO "https://dl.k8s.io/release/${VER}/bin/linux/amd64/kubectl"
curl -LO "https://dl.k8s.io/release/${VER}/bin/linux/amd64/kubectl.sha256"

echo "$(cat kubectl.sha256)  kubectl" | sha256sum --check
# kubectl: OK
```

Для серверных тарболов (`kubernetes-server-linux-amd64.tar.gz`) хеши SHA512 указаны на
странице релиза в GitHub (CHANGELOG). Сравнение вручную:

```bash
sha512sum kubernetes-server-linux-amd64.tar.gz
# сравнить с хешем со страницы релиза
```

На экзамене типичная формулировка: «в каталоге лежат несколько бинарников, удалите те, что не
совпадают с официальными хешами» или «проверьте, что kubelet на ноде совпадает с
официальным». Шаги:

```bash
# хеш установленного бинарника
sha512sum $(which kubelet)
kubelet --version          # узнаём версию, чтобы сравнить с правильным релизом

# распаковали официальный архив той же версии
tar xzf kubernetes-server-linux-amd64.tar.gz
sha512sum kubernetes/server/bin/kubelet

# сравнение двух файлов напрямую
cmp $(which kubelet) kubernetes/server/bin/kubelet && echo SAME
```

Полезный приём для сравнения длинных строк - положить ожидаемый хеш в файл и сделать
`sha512sum -c`:

```bash
echo "<ожидаемый_хеш>  /usr/bin/kubelet" > expected.sha512
sha512sum -c expected.sha512
```

## 6.3. Проверка подписи

Начиная с 1.26, артефакты релиза Kubernetes (бинарники и образы) подписываются через
**sigstore/cosign** (keyless-подпись). Проверка бинарника:

```bash
curl -LO https://dl.k8s.io/release/${VER}/bin/linux/amd64/kubectl.sig
curl -LO https://dl.k8s.io/release/${VER}/bin/linux/amd64/kubectl.cert

cosign verify-blob kubectl \
  --signature kubectl.sig \
  --certificate kubectl.cert \
  --certificate-identity krel-staging@k8s-releng-prod.iam.gserviceaccount.com \
  --certificate-oidc-issuer https://accounts.google.com
```

Точные значения identity/issuer берите из документации «Verify Signed Kubernetes Artifacts»
на kubernetes.io - они могут меняться. Подписи образов control plane проверяются
аналогично через `cosign verify` (глава 19).

## 6.4. Пакеты ОС

При установке через apt/yum целостность обеспечивает **подпись репозитория**: пакеты
`pkgs.k8s.io` подписаны GPG-ключом, который вы добавляете в `/etc/apt/keyrings/`. Не
отключайте проверку (`[trusted=yes]`, `--allow-unauthenticated`) и берите ключ только с
официального адреса.

## 6.5. Итоги главы

- Бинарники платформы - критичный актив: подмена = захват кластера.
- Целостность - хеш (`sha256sum --check`, `sha512sum`), подлинность - подпись cosign.
- Хеши kubectl/kubelet лежат рядом с бинарником на `dl.k8s.io`, SHA512 тарболов - на
  странице релиза.
- Сравнение: `sha512sum`, `sha512sum -c`, `cmp`.
- Для пакетов - подпись репозитория, никаких `trusted=yes`.

## Практика

Отдельной лабы пока нет. Самостоятельно на ноде любой лабы:

1. Определите версию `kubelet` и скачайте официальный бинарник той же версии и его `.sha256`.
2. Сравните хеш установленного и скачанного бинарника.
3. Испортите копию (`echo x >> kubectl-copy`) и убедитесь, что `sha256sum --check` падает.
